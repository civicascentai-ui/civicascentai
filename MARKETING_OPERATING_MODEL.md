# CivicAscent AI — Marketing Operating Model

## Standing rule
CivicAscent AI marketing uses a controlled, human-approved content pipeline. AI may create and revise content, but publication, claims, sensitive actions, and final release remain governed by CivicAscent approval gates.

## Core workflow
Idea → AI Draft → Brand Review → Accessibility Review → Claims / Compliance Review → Preview → Human Approval → Schedule / Publish → Analytics → Improve

## Content production pattern
One approved campaign idea should be reusable across channels:
1. Core video
2. Short vertical video
3. Website version
4. Social caption
5. Spanish adaptation
6. Email version

Reuse must preserve meaning, accessibility, brand integrity, and approval status.

## Initial campaign priorities
### 1. Beginner AI education
Short explanations of practical AI concepts in simple language.

### 2. Real-life AI use cases
Examples involving email, appointments, job preparation, learning, translation, organization, and everyday problem solving.

### 3. Community and organizational training
Campaigns for libraries, workforce groups, nonprofits, senior programs, schools, and community organizations.

## AI media / avatar policy
Higgsfield and other approved media tools may be evaluated for:
- branded video generation
- repeatable campaign templates
- fictional AI presenters
- product/service explainers
- short-form social content

AI-generated presenters must be clearly identified when required by platform rules or context. Fictional presenters must not be presented as real employees, customers, endorsers, or witnesses.

## Advertising integrity rules
CivicAscent marketing must not:
- invent customer testimonials
- fabricate partnerships or endorsements
- invent personal experience
- exaggerate measurable outcomes
- create unsupported training, employment, financial, or performance claims
- imply a demonstration proves a result that has not been verified
- publish misleading synthetic media

Visual demonstrations, before/after examples, statistics, comparisons, and capability claims must be supportable.

## Approval gate
No marketing asset moves to publishing until:
1. message is accurate
2. brand treatment is acceptable
3. accessibility checks pass
4. claims are supportable
5. security/privacy checks pass when relevant
6. required AI-content labeling is included
7. human approval is recorded

If changes are requested, the asset returns to revision and must pass the affected gates again.

## Tooling rule
Do not add a tool merely because another workflow uses it.

Prefer existing approved tools and the lowest-cost architecture that solves the problem. Additional services such as n8n, Airtable, Slack, Blotato, paid APIs, or other publishing platforms require separate evaluation for:
- need
- cost
- privacy
- security
- reliability
- accessibility
- integration burden

No paid add-on is approved by this document.

## OpenAI API rule
ChatGPT subscription access and OpenAI API billing are separate. Paid API usage is not automatically authorized for CivicAscent marketing. Use it only after explicit approval and a documented business need.

## Publishing principle
**AI creates. Agents review. Humans approve. Systems publish. Analytics improve the next cycle.**

## Analytics loop
After publication, capture only useful metrics such as:
- views / reach
- completion rate
- click-through rate
- inquiries
- consultation requests
- registrations
- accessibility or usability feedback
- repeated audience questions

Analytics inform the next campaign but never override accuracy, accessibility, mission fit, or governance.

## Permanent governance alignment
This marketing model is subordinate to all existing CivicAscent core rules:
- no-known-defect rule
- accessibility and mobile usability
- clear next action
- security/privacy review
- human escalation where failure matters
- no unapproved paid add-ons
- backups and isolated test branches
- no unauthorized production publishing, purchasing, deletion, account changes, or transactions
