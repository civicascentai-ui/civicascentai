# CIVICASCENT AI — PERMANENT PRE-CHANGE REVIEW LAW

Status: PERMANENT / SUPREME GOVERNANCE GATE  
Applies to: ChatGPT Governance/QC Overseer, Agents 1–6, Librarian, mentors, contractors, plugins, automation, code-generation tools, design tools, external resources, and any future agent or tool.  
Effective: 2026-09-29

## 1. Supremacy

No design, code, content, plugin, dependency, workflow, architecture, navigation, animation, accessibility behavior, production configuration, business-facing feature, or toolchain change may be made until this review is completed and recorded.

This law sits ABOVE all agents, agent charters, design systems, implementation plans, tool recommendations, and ordinary workflow instructions.

Only the project owner may explicitly override this law.

No agent may waive, bypass, shorten, self-approve, or reinterpret this gate for convenience.

## 2. Mandatory sequence

Every proposed change must follow this order:

1. PROPOSE
2. SAVE POINT
3. PRE-CHANGE REVIEW
4. GOVERNANCE DECISION
5. IMPLEMENT IN ISOLATION
6. TEST
7. INDEPENDENT REVIEW
8. OWNER/RELEASE AUTHORIZATION WHEN REQUIRED
9. PROMOTE OR REJECT
10. NEW SAVE POINT

If any step fails, STOP.

The no-known-defect rule remains absolute.

## 4. Automatic rejection conditions

A proposed change is automatically rejected or returned for revision if:

- the user problem is unclear;
- the change exists mainly because a tool or trend is fashionable;
- no rollback path exists;
- a required save point is missing;
- production must be modified just to test the idea;
- it introduces unapproved cost;
- it weakens accessibility or first-time-user clarity;
- it creates card/brochure/dashboard drift in the Safari experience;
- it adds motion without functional purpose;
- it duplicates an existing capability without a measurable advantage;
- it introduces a known defect;
- the test plan cannot prove success;
- agents materially disagree and the disagreement is unresolved;
- the source of truth is ambiguous.

## 5. Approval does not equal production

Passing this review only authorizes an ISOLATED TEST.

It does not authorize production deployment.

After implementation, the candidate must still pass:
- Agent 1 experience review;
- Agent 2 engineering verification;
- Agent 3 independent QA/accessibility review;
- Agent 4 critical evaluation where applicable;
- Agent 5 dependency/source audit where applicable;
- Agent 6 strategic review where applicable;
- no-known-defect gate;
- owner authorization whenever production promotion, spending, legal attestation, credentials, or other owner-only action is required.

## 6. Required record

Every approved change must leave an audit trail containing:

- proposal name;
- date/time;
- source build/branch;
- pre-change save point;
- completed Q&A review;
- agent findings;
- governance decision;
- implementation branch;
- test results;
- defects found and repairs;
- final decision;
- post-change save point.

No record = no valid approval.

## 7. Permanent operating rule

Before any change, ask:

**FIRST PRINCIPLES + BLIND SPOTS + LEVERAGE + ANTI-ADVICE + SIGNAL ONLY**

Then answer the full Pre-Change Review Template.

No answer, no change.
