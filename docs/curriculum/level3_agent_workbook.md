# CivicAscent AI — Level 3: Responsible AI Agent Teams and Verification
Version: 2026-10-14 · Status: REVIEW DRAFT, NOT AN OPEN COURSE
Audience: learners who completed Level 2 equivalents; no programming required. Four 60-minute sessions. Safe paper exercises accepted.
Purpose: teach what agents do, their limits, how to coordinate work, how to demand evidence, and when a human must approve consequential actions.

## Key concepts
An **AI agent workflow** can coordinate tasks and tools when configured. Calling a helper "SAM" or "ZEBRA" does not automatically create a running process. A **draft** is not a message sent; a **test plan** is not an executed test; a **preview** is not production; a **passed link check** is not full learner delivery. Never fabricate evidence.

## Session 1: Define a team (60 minutes)
**Explain (10 min).** Select one modest, measurable workflow; define done; then split roles. Too many agents can increase complexity.
**Model (10 min).** Fictional library workshop: CODI plans; SCOUT researches public facts; SAM prepares accessible materials; FRIDAY checks outcomes independently; ZEBRA challenges risks; REACH drafts community outreach but does not send; VET REP checks veteran relevance with human veteran reviewer still required.
**Exercise (25 min).** Fill the role chart:
| Role | Input | Safe task | Output | Handoff | Human approval? |
| --- | --- | --- | --- | --- | --- |
| CODI | | | | | |

| SAM | | | | | |
| FRIDAY | | | | | |
| ZEBRA | | | | | |
| REACH | | | | | |
| VET REP | | | | | |
**Debrief (10 min).** Assign only one owner for each deliverable, and distinguish advisory roles from active tools.
**Exit ticket (5 min).** Explain why the maker should not certify their own final QC.

## Session 2: Create safe task instructions (60 minutes)
**Explain (10 min).** Clear task packet: role, goal, input, constraints, expected output, allowed tools, evidence, testing, and handoff.
**Demonstrate (10 min).** “SCOUT /choose: Find three free, official resources for a fictional workshop. Do not invent access, spend money, use private files, or send messages. Return sources with dates and uncertain items flagged.”
**Exercise (25 min).** Give a role a task and write all eight packet fields. Mark simulated outputs SIMULATED; don't paste credentials or private student records.
**Debrief (10 min).** A system prompt does not grant permissions. The execution environment determines what actually runs.
**Exit ticket (5 min).** Label each: “File committed,” “Agent executed,” “Human approved,” “Email sent.” Which require separate evidence?

## Session 3: Independent QA and incident handling (60 minutes)
**Explain (10 min).** Check five representative scenarios and three failures before release.
**Model (10 min).** Fictional course-packet link tests: expected lesson exists, missing file, unreadable text, wrong language, unsafe payment link. Record actual results only after running checks.
**Exercise (25 min).** Draw a quality matrix using Case / Expected / Actual / Evidence / Pass-Fail-Not Run / Assigned Fix. Leave Actual and Evidence blank if no test occurred.
**Debrief (10 min).** Independent reviewer lists defects, SAM prepares repairs, FRIDAY retests, ZEBRA checks risk; CODI records the evidence and asks owner approval to publish.
**Exit ticket (5 min).** Why does “all tests planned” not mean “QA passed”?

## Session 4: Responsible end-to-end team project (60 minutes)
**Challenge.** Prepare a fictional, accessible free AI workshop, never a real sales or benefits claim.
- CODI defines done as a clear one-page lesson plan and learner handout.
- SCOUT identifies possible public information sources, clearly marked unverified until checked.
- SAM drafts a printable handout using fictional inputs and no sensitive data.
- FRIDAY records independent checks, including keyboard/large-text suitability.
- ZEBRA lists three risks (privacy, invented facts, nonexistent runtime).
- REACH drafts an UNSENT invitation.
- VET REP reviews relevance and notes that actual outside veteran feedback is pending.
**Present (15 min).** Provide evidence for every step actually executed and a one-line blocker if not done.

## Assessment questions
1. Does assigning a name to a role prove an agent is running?
2. Can FRIDAY pass a project without evidence of executing tests?
3. What is required before real outreach emails are sent?
4. A generated source citation is broken. What should SCOUT do?
5. Why is independent veteran feedback different from VET REP AI output?
6. Who checks a SAM repair before a user-facing release?
7. What should the team report when deployment appears READY but learner access is untested?
8. Should a failed test be renamed "pass" to meet a deadline?

### Facilitator answer key
1. No, a configured runner and evidence of actual execution are needed.
2. No, planned cases must be marked NOT RUN until executed.
3. Explicit owner approval and verified recipients/content.
4. Mark the claim unverified, replace with a trusted checked source or omit it.
5. AI role recommendations are not actual lived-experience validation from a person.
6. FRIDAY independently retests and ZEBRA reviews relevant risks, then the owner approves release.
7. Deployment confirmed; delivery unverified and launch gate blocked.
8. No; document defect, correct, retest.

## Rubric (0–2 each; 12 points)
| Criterion | 0 | 1 | 2 |
| --- | --- | --- | --- |
| Defined outcome | Missing | Vague | Concrete and measurable |
| Agent responsibility | Overlap/no owner | Some clarity | Named owner and safe handoffs |
| Permissions/privacy | Unsafe | Partial | Explicitly constrained |
| Independent QC | Self-approved | Role named | Evidence and reviewer separated |
| Truthful status | Unfounded claims | Mixed | Planned/executed/verified separated |
| Human approval | Missing | Mentioned | Explicit gated triggers |
Guide: 10/12 with no unauthorized action is a suggested criterion, not a claim of completed certification.
