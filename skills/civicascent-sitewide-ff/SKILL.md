## Accessibility and QC rules
- Target WCAG 2.2 AA and high cognitive usability; no full certification claim from browser tests alone.
- Meaningful landmarks, page language, skip links that actually focus content, reliable button/field labels, visible keyboard focus on all backgrounds, proper error and live status messages.
- Normal text contrast generally >=4.5:1, large text >=3:1, applicable non-text/focus >=3:1. Check actual backgrounds, not just brand palette.
- Test viewport widths 320,390,768,1024,1366 and browser zoom/reflow; check keyboard, responsive cards, links, forms, text controls, user-initiated speech, reduced motion and mobile devices. Manual TalkBack/VoiceOver/NVDA and older/veteran learner testing remain separate gates.
- No payment requests in public production stress tests. Paid checkout remains fail-closed and HOLD; no purchase approvals or billing.

## FF standard, invoked by "FF"
1. Find: inspect approved owner images, classify live vs source, identify exact defect, prioritize safety/hard deadlines, save baseline Git SHA.
2. Fix: smallest reversible change on isolated work branch. Preserve educational content, page meaning, privacy, no-charge rules and broken-link avoidance.
3. Retest: run old and new relevant tests, preserve failures honestly, use actual Chromium screenshots at mobile/desktop, verify keyboard navigation and route links, repair and rerun until evidenced PASS or a real blocker.
4. Save: record tested commit SHA, screenshots/test URLs, rollback point, open checks and owner decisions.
5. Release: only with authorization; verify correct Vercel team/project and deployment SHA, production domain and post-release smoke. Free-plan rate limiting is a blocker, not permission to activate charges.
6. Report succinctly: Completed, In Progress, Blocked, Overdue, Next Actions, Decisions Needed and role-specific pros/cons where requested. Do not invent autonomous agents or tests.
