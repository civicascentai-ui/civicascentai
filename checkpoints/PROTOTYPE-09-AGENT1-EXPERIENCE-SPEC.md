# Prototype 09 — Safari Learning World
## Agent 1 Experience Specification

Date: 2026-09-28
Status: AGENT 1 DELIVERABLE / PENDING QC APPROVAL

## 1. Experience Goal
Prototype 09 must feel like entering a living, premium Safari learning environment rather than visiting a conventional website.

The environment itself is the interface.

The experience must be cinematic, calm, readable, useful, and immediately understandable to an older adult or first-time AI user.

The visual reference is the center concept from the approved three-direction review:
**Safari Learning World**.

## 2. Primary Scene
The opening environment is a golden-hour African savanna viewed from an elevated lodge or terrace.

Required visual anchors:
- warm sunset and long golden light
- expansive layered savanna
- watering hole or shallow river
- elephants as the dominant living wildlife event
- giraffes and distant wildlife as secondary atmosphere
- acacia trees and layered vegetation
- mountain / mesa depth on the horizon
- realistic water reflections
- atmospheric haze
- premium lodge / terrace framing in foreground
- strong foreground, midground, and background separation

The visual result must feel photorealistic or premium cinematic CGI, never procedural, clip-art-like, or game-like.

## 3. Visual Hierarchy
The visitor's eye should read the scene in this order:
1. dominant living wildlife event
2. environmental destination / next action
3. supporting landscape depth
4. secondary wildlife and ambient motion
5. minimal supporting text

The environment must stay visually rich while attention remains simple.

## 4. Living Canvas Motion
The world must already feel alive before the visitor touches anything.

Allowed dominant motion systems:
- water movement and reflections
- slow wildlife movement
- foliage / grass movement
- atmospheric haze / drifting dust / light
- nearly invisible camera drift or parallax

Secondary micro-motion is allowed only when it does not create a competing focal point.

One dominant wildlife story at a time.

Camera motion must be purposeful and nearly invisible.

## 5. Environmental Navigation
Navigation must be embedded into the world.

Do not use:
- card grids
- dashboard tiles
- floating pill menus
- brochure sections
- Roblox/game HUD patterns
- generic website hero + stacked content sections

Approved interaction pattern:
- labeled environmental destinations
- subtle hotspot markers tied to real scene objects
- illuminated paths, structures, signs, objects, or locations
- short contextual text appearing near the destination
- clear visual cue showing what happens next

Every interactive destination must answer:
**What is this?**
**Why would I click it?**
**What happens next?**

## 6. First-Time User Clarity
The first screen must provide one obvious next action.

Text must be short, large, and plain-language.

Example intent:
- "Explore how AI can help you"
- one clear primary destination
- secondary destinations remain visible but visually quieter

No jargon-first presentation.

## 7. Learning Journey
Prototype 09 should support a simple beginner progression:

**See it → Try it → Understand it → Use it**

The learning world may contain destinations for:
- Learning with AI
- Creating with AI
- Everyday help
- Business and opportunity
- Spanish / bilingual learning
- Living AI Lab
- Programs / training

These are experience destinations, not card modules.

## 8. Voice Behavior
When approved for later implementation:
- hotspot click may trigger a short spoken introduction
- voice must sound natural, calm, slightly slower, and non-robotic
- voice must never block navigation
- captions / text equivalent required
- user must have control to stop or mute audio

Voice is supporting guidance, not the primary interface.

## 9. Accessibility Intent
The experience must be designed for older adults and first-time AI users.

Mandatory:
- large readable type
- strong contrast
- clear focus states
- touch targets sized for mobile use
- no interaction dependent only on color
- reduced-motion mode
- no rapid flashes
- no essential information hidden behind hover
- readable labels against complex imagery
- keyboard-accessible interaction paths
- captions / text alternatives for voice
- obvious return / back path

Accessibility must be part of the visual composition, not added afterward.

## 10. Mobile Experience
Mobile must preserve the living-world concept.

Do not flatten the site into cards on mobile.

Mobile adaptation should:
- crop and recompose the scene intentionally
- keep one dominant focal event
- preserve environmental destinations
- simplify secondary motion
- maintain large type and touch targets
- reduce GPU-heavy effects when necessary
- preserve visual depth through layering and motion
- keep the next action obvious without scrolling to discover it

## 11. Performance Intent
The experience must look premium without becoming unusable.

Agent 2 must later implement against a performance budget.

Agent 1 requirements:
- use cinematic media selectively
- preserve one dominant visual event
- avoid unnecessary simultaneous animation
- favor layered compositing over gratuitous heavy 3D
- retain graceful fallback for slower devices
- no paid dependency required to render the base experience

## 12. Business Effectiveness
Prototype 09 must support the business, not merely impress visually.

Experience must guide users toward measurable outcomes:
- start learning
- explore a capability
- view a program
- purchase training
- request information
- return for continued learning

The path from cinematic discovery to practical action must be obvious.

## 13. SEO / Structure Intent
The immersive front end must still sit on a crawlable, structured site.

Required later implementation:
- semantic headings
- crawlable text equivalents
- descriptive page titles
- meaningful URLs
- structured navigation
- indexable program / learning pages
- internal linking
- fast load behavior
- metadata and schema where appropriate

The visual experience must not erase the informational architecture.

## 14. Conversion Strategy
The experience should build confidence before asking for commitment.

Sequence:
1. emotional / visual engagement
2. clear demonstration of AI value
3. low-friction exploration
4. practical benefit
5. next-step action

Do not lead with aggressive sales treatment.

## 15. Explicitly Rejected Directions
The following are prohibited:
- Safari React Prototype A visual treatment
- dark procedural gradients as the primary environment
- crude CSS wildlife shapes
- train / transit / station worlds
- starflight / space intro as primary direction
- winter lodge direction
- Living Art Museum direction
- Africa Pavilion + Safari Hybrid direction
- brochure-card layouts
- generic SaaS dashboard layouts
- game-like navigation
- static hero image with conventional sections beneath it
- dense menus competing with the environment

## 16. Acceptance Test for Agent 1
Before engineering begins, QC must answer YES to all:

1. Does this feel like Prototype 09?
2. Is the Safari environment clearly the interface?
3. Is the scene rich without becoming confusing?
4. Is the next action obvious to someone new to AI?
5. Is the experience appropriate for older users?
6. Is there a clear mobile strategy?
7. Is the business path present without turning the scene into a sales page?
8. Are accessibility requirements built in?
9. Are the rejected directions explicitly excluded?
10. Can Agent 2 implement this without inventing the visual direction?

If any answer is NO, Agent 1 must revise before Agent 2 begins.
